Recommended contract · Rust v2

Ship the simpler journey without spending compatibility.

One install gives users siloscan, ss, and report review. A bare command detects, scans once, saves one latest report, and exits. Existing explicit invocations keep their v1.5.1 behavior. Published artifacts remain immutable.

Decision Add the automatic journey beside the old contract.

Keep the Rust implementation. Preserve the public report writer, schema 1.2, fingerprint algorithm, baseline v1, aliases, standalone TUI, machine streams, archive members, and all explicit scan behavior for the full v2 major.

  • No feature is removed or silently weakened.
  • No ecosystem rules are invented for launch.
  • Security hardening is outside this decision.
  • The only default change is true automatic mode.

Automatic means narrow

Only invocations with no PATH and no v1 scan option enter automatic mode. New persistence-only controls do not turn that invocation into legacy mode.

Option-only scripts remain scripts

siloscan --format json is explicit compatibility mode and stateless. Adding --save requests persistence without changing scan semantics.

No fake project root

Latest is keyed by the exact requested scope. Detection never promotes the scope to a Git root, manifest root, workspace root, or “owning project.”

Approved TUI setup convergence

v2 removes the standalone TUI’s duplicated setup path and gives siloscan review --live PATH and siloscan-tui PATH the same fresh resolved plan. This can correct v1.5.1 drift such as a config-anchored baseline being resolved from the wrong base. There is no legacy drift mode. Commands and actions remain, every r resolves fresh, and live TUI sessions never auto-publish latest.

Report evolution

Schema 1.2 stays. Marker completeness decides meaning.

Product version cannot classify the document. The retained public core writer will naturally emit a 2.x product version without resolved metadata. The four v2 marker fields are therefore the only reliable discriminator.

Compatibility arbitration

This issue #60 contract explicitly supersedes one clause from the closed saved-report decision in issue #61: product major 2 or later no longer selects strict resolved-report validation. Marker completeness does. That narrower correction is required by issue #63’s retained public core writer, which emits product version 2.x without resolved metadata. Every other #61 persistence, shape, identity, atomic-publication, and failure contract remains in force.

Reader classification

  • No marker present: legacy/core shape. Require a findings array and either supported schema 1.x or no schema key, which means 1.0. Explicit --report may open it.
  • Any marker present: require all four complete fields and report_kind: "scan". A partial set is malformed.
  • Implicit latest: require the complete marked v2 shape. Never treat a loose legacy document as latest.
  • Product version: validate its syntax when present and display it. Its major does not classify the shape or relax validation.
  • Same-major additions: ignore unknown fields and retain an unknown-string case for setup status enums, so a later additive value does not invalidate the report.

Deterministic metadata only

scope, outcome, and setup serialize requested-scope identity, threshold result, admitted evidence, units, workspaces, languages, source roots, rule sources, capabilities, and explicit overrides. Stable arrays use deterministic order. The canonical saved document ends with exactly one newline.

Never serialize environment identity

No absolute root, cwd, hostname, command line, report path, cache path, manifest text, runtime handle, or timestamp. Those are not scan facts and make exact reports needlessly unstable.

One intentional malformed-input break

v2 rejects a marker-free object whose findings value is absent or null, including a schema-only object. v1.5.1 could render those impostors as an empty report. No shipped writer produced them, and accepting them can falsely present arbitrary JSON as a clean scan.

Latest destination hint

Bare or --save uses Review: <invoked-bin> review [PATH]. siloscan and ss name themselves correctly.

Named destination hint

--output FILE uses Review: <invoked-bin> review --report FILE. It never points at latest because that destination was not updated.

Performance rule

Paths

Explicit unchanged: no-cache, cold, warm. Bare reference versus v2 --no-save: cold, warm. Bare reference versus auto-save: cold first publication, warm replacement.

Method

Nine paired ABBA samples on one GitHub Actions runner. Compare wall time and OS peak RSS medians independently. Keep raw samples as artifacts.

Decision

Ratio above 1.05 is suspected. Repeat the complete pair on a fresh runner. The same path, cache state, and metric above 1.05 twice blocks. Reference MAD above 20% invalidates the run. Faster lanes never offset slower ones.

Release train

Qualify first. Publish once.

GitHub CI owns repository-level proof. Local verification stays targeted to the changed contracts, as requested.

1 · CandidatePin one commit. Build no public release.
2 · TargetedRun only tests for changed code and contracts.
3 · OracleCompare v1.5.1, reports, readers, aliases, baselines, and performance.
4 · ArchivesBuild release shape, extract, and smoke three binaries natively.

Registry order is a contract

v2 CLI depends on the TUI library. The only legal crates.io order is siloscan-core → siloscan-tui → siloscan, with registry-index availability verified before publishing each dependent crate.

Current baseline is not release-ready

Exact-main GitHub Actions run 33348294251 is red in Linux Clippy under Rust 1.98. Current workflows also lack the full compatibility, performance, exact-SHA, extracted-archive, and install gates. The v2 candidate cannot inherit a green label from partial jobs or another SHA.

Rollback

Rollback means a new state, not rewritten history.

Before publication

Block and replace the candidate

A compatibility diff, malformed report, baseline shift, repeated performance regression, archive failure, or stale CI blocks tagging. Fix on a new commit and rerun every affected gate.

Partial crates publish

Hold, then resume or patch

Published versions cannot be overwritten. For a transient registry failure, resume the remaining same-version sequence. For a product defect, yank only unusable v2 crates and publish a corrected patch from a new commit.

After public release

Preserve and supersede

Keep the tag and assets immutable. Users can pin 1.5.1. Preserve baseline v1, publish v2.0.1 from a new commit, and yank only a release that is unusable. Never move a tag, replace public assets, delete user reports, or pretend a published crate did not exist.

Non-waivable blockers

Explicit behavior diff, partial v2 marker set, baseline or fingerprint shift, failed native archive smoke, repeated same-lane performance ratio above 1.05, or GitHub CI that is missing or belongs to another SHA.

Boundaries

What v2 does not smuggle into the release.

No rule-policy expansion

Project detection never invents architecture silos, coverage thresholds, suppressions, baselines, source filtering, severity policy, generated-code policy, or a primary ecosystem.

No ecosystem add-ons

Launch keeps the unchanged default secret pack and metrics. A future profile needs a new version plus evidence for noise, compatibility, and cost. Build capability alone is not evidence.

No security-hardening detour

Security hardening is excluded. Existing secret detection is still a shipped feature and remains protected by the no-regression oracle.
