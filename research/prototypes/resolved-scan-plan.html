One scan plan.
One admitted inventory.

A concrete Rust ownership seam for zero-config detection without moving policy into the CLI, duplicating setup in the TUI, walking twice, or changing the existing engine contracts.

The recommendation

Public, opaque ResolvedScanPlan in siloscan-core.
  • Private fields, no serialization, no public struct literal.
  • Own loaded setup; derive borrowed ScanOptions only while executing.
  • Move one prepared inventory into the existing engines.
  • Return a resolved-report wrapper, leaving public ScanReport source-compatible.

Why it must be public

The CLI and TUI are separately published crates. Rust has no workspace-private visibility. #[doc(hidden)] is still public API, and a session wrapper merely gives the same contract another name.

Owning seam

Resolution happens once, at the core boundary.

The CLI keeps arguments, persistence, presentation, and exit status. The TUI keeps terminal behavior. Core becomes the only owner of config, rules, baseline, cache, detection, and scan inputs.

01 · REQUEST

Preserve intent

Exact requested path plus whether PATH was omitted. Explicit overrides remain distinguishable.

02 · STATIC SETUP

Load stronger inputs

Config, anchoring, walk policy, baseline source, coverage source, and cache location.

03 · INVENTORY

Walk once

Use current ignore and symlink rules. Remove the cache-owned path before detection.

04 · RESOLVE

Detect and freeze

Project facts, additive profile selection, final rules, cache key, evidence, and capabilities.

05 · EXECUTE

Reuse engines

Build temporary ScanOptions and move the admitted inventory into the existing scanner.

Concrete Rust contract

A small public surface, not a public data dump.

The executable plan is opaque. The serialized explanation is a separate deterministic value. This keeps parser internals and runtime handles out of semver and out of reports.

Destructure before borrowing

pub fn execute(
    self,
    progress: &mut dyn FnMut(Progress),
) -> Result<ResolvedScanReport, String> {
    let ResolvedScanPlanInner {
        request: _, root, baseline_root, anchoring,
        config, rules, baseline, coverage, cache,
        ignore, follow_symlinks, inventory, setup,
    } = self.inner;

    let scan = {
        let mut options = ScanOptions::default();
        options.baseline = baseline.as_deref();
        options.cache = cache.as_deref();
        options.config = config.as_deref();
        options.coverage = coverage.as_deref();
        options.ignore = ignore;
        options.follow_symlinks = follow_symlinks;

        scan_prepared(
            &root, &rules, &options, inventory,
            &anchoring, progress,
        )?
    }; // all temporary borrows end here

    let output = ScanOutputContext {
        root, baseline_root, anchoring, rules, config,
    };
    Ok(ResolvedScanReport { scan, setup, output })
}

The plan never stores ScanOptions. Destructuring first makes the inventory an independent owned local; the temporary options borrow only sibling locals and are dropped before those values move into the output context.

#[non_exhaustive]
pub enum CapabilityStatus {

pub struct CapabilityState {
    id: String,
    status: CapabilityStatus,
    reason: Option<String>,

impl CapabilityState {
    pub fn enabled(id: impl Into<String>) -> Self;

    pub fn not_enabled(
        id: impl Into<String>,
        status: CapabilityStatus,
        reason: impl Into<String>,
    ) -> Self;

    pub fn id(&self) -> &str;
    pub fn status(&self) -> &CapabilityStatus;
    pub fn reason(&self) -> Option<&str>;
}

The constructor requires a reason for every non-enabled state, while accessors keep the report inspectable by the TUI and Rust embedders without making its representation public. Final vectors are sorted by normalized relative path, ecosystem, kind, then stable string ID. The JSON writer preserves all existing fields, appends report_kind, scope, outcome, then setup. SARIF stays unchanged.

Never serialize the canonical absolute root, working directory, command line, cache path, persistence destination, manifest text, host, or timestamp.

CLI consumes one plan

let destination = persistence.preflight(&args)?;
let request = scan_request_from_clap(args);

let mut resolved =
    ResolvedScanPlan::resolve(&request)?
        .execute(&mut |_| {})?;

let failed = fails_before_filter(&resolved.scan);

Scope and destination preflight happens before the expensive walk. Format, filtering, persistence publication, stdout routing, and process exit remain in the CLI.

TUI consumes one fresh plan per scan

pub enum ReviewSession {
    SavedReport { /* no scan request */ },
    Live { request: ScanRequest },
}

// Initial scan and every r:
let request = request.clone();
thread::spawn(move || {
    let result = match ResolvedScanPlan::resolve(&request) {
        Ok(plan) => plan.execute(&mut send_progress),
        Err(error) => Err(error.to_string()),
    };
    send_result(result)
});

The TUI retains only the owned request between scans. It does not reload setup itself. A new immutable plan sees added files, removed files, changed evidence, and the reloaded baseline.

Field-by-field precedence

Detection fills gaps. It never becomes policy.

Explicit inputs and current config semantics stay authoritative. Project evidence adds facts and, only on the omitted-PATH journey, may enable low-noise embedded profiles chosen by the next ticket.

Resolved field Precedence Hard boundary
Scan root Exact PATH, otherwise . Never promote to Git, manifest, workspace, or common root.
Config Explicit file → current bounded discovery and owning-root include logic → none Malformed Siloscan config remains fatal.
Anchor, silos, limits, source roots Loaded config → current defaults Detected hints do not rewrite config or invent architecture.
Language mapping Working config mapping → current extension inference The currently inert config field is not reported as active until wired or rejected.
Embedded rules Current default pack → automatic-journey detected profiles --no-default-rules disables both groups.
Rule directories Explicit directories → config directories Current load order and duplicate-ID refusal remain.
Detected profiles Eligible only when PATH was omitted Explicit-path scans record metadata but cannot change findings.
Baseline Explicit file → current anchor-aware default → absent Detection cannot create, relocate, or accept a baseline.
Coverage Explicit report only Detection cannot invent coverage data or thresholds.
Cache Disable → explicit directory → current platform default Exclude location before detection; bind key after final rules.
Walk Explicit ignore/symlink flags → current defaults Detector reads the admitted inventory and never traverses again.
Persistence and output CLI request only Outside the plan. Detection never selects save, format, filter, or exit status.
Design comparison

Three viable shapes. One has fewer lies.

The comparison is included for auditability. The recommendation is already selected; this is not a request to choose among them.

Shape Strength Cost Verdict
Public plan with public fields Easy to inspect and construct. Freezes loader state, detector internals, cache ownership, and future fields into semver. Reject
Private plan behind public session wrapper Can rename internal plan fields freely. The wrapper exposes the same lifecycle contract under another concept and complicates rescans. Reject
Public opaque plan + resolved report wrapper Honest cross-crate API, one owning value, existing ScanReport remains intact. A small new stable constructor/execution contract. Recommend
Compatibility Legacy scan entry points, fields, findings, fingerprints, outputs, and engine behavior remain.
Fresh TUI rescans The TUI retains ScanRequest and resolves a new immutable plan for every r.
Performance One walk, one inventory, no report clone, no per-unit scan, and final cache binding only once.
Determinism Sorted relative facts, stable status strings, reasons for every non-enabled capability.
Persistence sequencing CLI preflights scope and destination before the expensive resolve-and-scan phase.
Stop gate No implementation accepted above 5% repeated cold, warm, or peak-RSS regression.
