# siloscan 2.2.0 — Production-Readiness Verdict

## 1. Verdict

**DO NOT SHIP** (narrowly — the blocking set is four small patches, not a rewrite).

Two defects put the product's own guarantee at risk on ordinary input: the boundary engine silently drops `use crate::{...}` imports, so the gate the tool is named for passes on violations it was configured to catch, and the read path has no size ceiling anywhere, so a vendored or generated tree OOM-kills the scan with no partial report and no skip entry. A scanner whose output is consumed as a CI pass/fail cannot ship a silent false negative in a headline feature; everything else here — engine arithmetic, cache design, determinism, release pipeline — is above the bar for 2.x.

## 2. Blockers

**B1. Boundary engine never resolves brace-grouped imports — denied dependencies report zero violations** (high)
`crates/siloscan-core/src/engines/boundary.rs:238-265`, capture at `crates/siloscan-core/src/graph.rs:271`.
`rust_candidates` truncates at the first `{`, so `use crate::{db::Pool, util};` yields `segments == ["crate"]`, `rest == []`, the candidate loop `for len in (1..=0).rev()` never runs, `resolve` returns `None`, and `scan_graph` `continue`s. No violation, no `skipped` entry, no warning. The same truncation also mis-resolves the non-empty case: `use crate::shared::{db::Pool};` resolves to `src/shared`, the wrong silo. This is the shape `rustfmt` emits under `imports_granularity = "Crate"`; siloscan's own crates have 5 of 87 internal `use`s in the unresolvable form.
Fix: expand the use tree before generating candidates — split the brace body on top-level commas and recurse with `head + leaf`. Add the missing regression `use crate::{db::Pool}` alongside the existing `crate::db::{Pool, Row}` case at boundary.rs:698.

**B2. No file-size limit on the read path; the whole tree's text is held resident** (high)
`crates/siloscan-core/src/walk.rs:1054` (`read_text` = uncapped `fs::read`), retention at `crates/siloscan-core/src/scan.rs:581`/`:707`, released only at `:799`.
`limits.max_parse_bytes` gates tree-sitter only — scan.rs:1234 says over-cap files "still go through every engine that works on text". `WalkBuilder` never calls `max_filesize`, which the `ignore` crate offers. Only VCS and `.siloscan` dirs are pruned, so a committed `node_modules`/`dist`/`vendor` is read whole, and up to `MAX_WORKERS = 32` workers can each hold a multi-hundred-MB file. `scan_one` reads before any cache lookup (scan.rs:1386), so a warm run has the same peak. Outcome is exit 137 mid-scan with no report and no way to configure around it.
Fix: add `limits.max_file_bytes`, enforce with `fs::metadata().len()` before `fs::read`, and route over-cap files into the existing `SkippedFile` plumbing with a stated reason. Separately, stop retaining `content` past the file that produced it.

**B3. Rule-directory discovery follows symlinks with no depth or containment guard, driven by the scanned repo's own config** (medium severity, blocking because the input is untrusted by design and the fix is one line)
`crates/siloscan-core/src/rules.rs:636-654`.
`path.is_dir()` uses `fs::metadata`, which follows symlinks; the recursion has no depth counter and no root check. `config::discover` returns the scanned root's own `siloscan.toml` unconditionally (config.rs:229), and `Plan::resolve` loads rule dirs before the walk (plan.rs:356-359), so a committed `rules = ["rules"]` plus a symlink is enough. `contain`/`confine` (config.rs:265-270, :498) guard only the declared entry; nothing re-checks children. `rules/loop -> .` recurses until `ENAMETOOLONG` and aborts the scan with a 4 KB path in the error; `rules/x -> /` walks the host filesystem reading every `*.yaml`/`*.yml` until the first non-rule document aborts the run, echoing an absolute path from outside the repo into the build log.
Fix: use `entry.file_type()` (does not follow symlinks) instead of `path.is_dir()`, matching what walk.rs already does for scanned files; optionally re-`confine` each child against the declared root.

**B4. Saved-report `path` is joined to the source base with no containment check** (high — **unverified**, no adversarial pass)
`crates/siloscan-tui/src/ui/triage.rs:914`.
`review --report FILE` is the documented way to open a report produced on another machine, so the file is untrusted input. An absolute or `..` path renders arbitrary file contents in the code pane under an attacker-chosen label; a FIFO or `/dev/zero` path blocks or OOMs inside `draw()` on the UI thread while crossterm raw mode has cleared ISIG, so Ctrl-C never reaches the process and the terminal must be recovered from another shell. Verify this before ship; if it holds, containment plus a regular-file check plus a size cap on the code-pane read are the fix.

## 3. Should fix soon

Ordered worst first.

- **Quadratic UTF-16 column on long lines** — `crates/siloscan-core/src/engines/mod.rs:97` and `:123`. `utf16_column` re-walks `content[line_start..offset]` per match; on a newline-free file `line_start` is 0, so cost is O(matches × line length). Callers: `engines/regex.rs:35`, `engines/secret.rs:97`, plus `cache.rs:463` on every cache hit, so warm runs pay it too. Fix: carry a running UTF-16 count forward between matches on the same line, or short-circuit `prefix.is_ascii()`. Pairs with B2 (`max_file_bytes`) to close the crafted-input case.
- **Duplication pass is unconditional, unconfigurable and single-threaded** — `crates/siloscan-core/src/scan.rs:799`, `crates/siloscan-core/src/metrics.rs:271`. ~150-200 B per non-blank line of the whole tree on top of the retained text, built even when `report_blocks` is false and no duplication rule is loaded; `min_lines < 2` is rejected at config.rs:278 so the `min_lines == 0` escape is unreachable. `window_key` is recomputed at metrics.rs:330 after metrics.rs:319 — two SHA-256 passes per window for nothing. Gate the call on `report_duplicate_blocks(...) || any Duplication rule`, and fix the double hash.
- **No scheduled advisory monitoring, and tags never run cargo-deny** — `.github/workflows/ci.yml:3-6`, `:146`; `.github/workflows/release.yml:3-5`. `cargo deny --locked check` fires only on push-to-main and PRs; ci.yml has no `workflow_dispatch` and no cron (the only cron is codeql.yml:17). Because release.yml triggers on tags and ci.yml's push trigger is `branches: [main]`, the tagged tree is never advisory-checked, contradicting DESIGN.md:1294. Add a scheduled advisories-only job, `workflow_dispatch`, and a tag-path run; add `.github/dependabot.yml` for cargo and github-actions.
- **Fingerprint ordinal absorbs new findings** — `crates/siloscan-core/src/findings.rs:59`, occurrence minted at `engines/mod.rs:63`. For rules whose reported span is a bare token (`reliability.rust.unimplemented-marker` reports `"todo"`; anonymous functions report `"("` / `"|"` via `metric.rs:669`), the only discriminator is a per-file count. Delete one baselined `todo!()` and add a new one in the same file and the new one is classified baselined; `baseline::partition` (baseline.rs:171) matches on fingerprint alone and nothing reports a baseline entry that stopped matching. Note this is PHPStan-baseline semantics and is documented in DESIGN.md:802/895-910; the cheap win is reporting unmatched baseline entries so absorption is visible.
- **stdout write and flush errors are discarded** — `crates/siloscan/src/main.rs:824`. `--format sarif > out.sarif` on a full disk writes a truncated file and exits 0, breaking the documented "a broken setup never reads as a pass" contract. (unverified)
- **TUI has no SIGTERM/SIGHUP handling and no worker-panic coordination** — `crates/siloscan-tui/src/term.rs:55`, `crates/siloscan-tui/src/app.rs:38`. A kill, job timeout or closed emulator leaves raw mode on and the alternate screen active; a panic on the scan thread restores the terminal while the UI thread keeps drawing into it and leaves `scan_running` stuck true, making `r` dead (lib.rs:220). (unverified)
- **Code pane re-reads the whole selected file every frame at 20 Hz on the UI thread** — `crates/siloscan-tui/src/ui/ratchet.rs:252`. (unverified)
- **Per-file memory is 2× for no reason, twice** — `crates/siloscan-core/src/scan.rs:1611` (`entry_hash` copies the file to compute the cache key, so `--no-cache` uses *less* memory) and `crates/siloscan-core/src/engines/secret.rs:48` (full lowercase copy for a boolean prefilter). (unverified)
- **Cache entries keyed on `CARGO_PKG_VERSION` only** — `crates/siloscan-core/src/cache.rs:687`. Two embedders of siloscan-core 2.2.0 with different grammar features share entries under the same salt and path scope; the full-grammar build reports zero AST findings for files the reduced build cached, exit 0, nothing in the report. Same hazard for any engine change at an unbumped version. (unverified)
- **Untrusted repo supplies rule patterns against a 32 MiB `PATTERN_SIZE_LIMIT`** — `crates/siloscan-core/src/rules.rs:21`, YAML parsed at `:664` with no document-size or alias limit. Unbounded compile-time resource consumption from repo content; not a ReDoS. (unverified)
- **Scan/silo-scope duplication gates emit SARIF `artifactLocation` of `"."`** — `crates/siloscan-core/src/engines/duplication.rs:214`. The gate fires in JSON and human output and is unplaceable in the channel most CI reads. (unverified)
- **Published library leaks `tree_sitter` / `globset` / `regex` types in its public API** — `crates/siloscan-core/src/parsers.rs:28`. A 0.x grammar bump in a 2.2.x patch is an unannounced breaking change for embedders. (unverified)
- **MSRV 1.96 verified on Linux only** — `.github/workflows/ci.yml:113`; the `objc2` and `windows-*` trees are never compiled at 1.96. **Release artifacts are unsigned with no provenance** — `.github/workflows/release.yml:206`; a SHA256SUMS uploaded beside the archive it describes verifies transport, not authorship. **Shipping binaries are built on an unpinned toolchain** — `scripts/candidate_manifest.py:168` compares archive names, not bytes, and there is no `rust-toolchain.toml`. (all unverified)
- **A release gate passes itself when the feature under test is missing** — `.github/workflows/release.yml:391`. The last user-journey gate fails open; every other gate in the repo fails closed. (unverified)
- **Docs** — `REFERENCE.md:3` documents 2 of 7 rule payload types, so boundary, coverage, ast, duplication and metric rules are advertised but unwritable; `anchor`, `include`, `limits` and `cache prune` are undocumented; nothing states that siloscan scans the working tree only and never git history, which for a secret scanner turns a clean exit into an unqualified all-clear; `CHANGELOG.md:169` dates a 2.1.0 that was never tagged; `README.md:43` promises macOS/Windows/Linux archives while three triples ship (no Intel macOS, no arm64 Linux); `crates/siloscan-core/README.md:8` omits the metric engine. (all unverified)
- **Abandoned cache temp files are never pruned** — `crates/siloscan-core/src/cache.rs:1418`; leaked bodies contain the path/rule/line inventory the module docs call sensitive. (unverified)

## 4. What is genuinely solid

- **Secret redaction has no leak.** `Finding.matched` holds the raw credential and every sink refuses it: JSON via one `payload_redacts` predicate (output.rs:210-236), SARIF with no `snippet`/`artifactContent` at all, the human listing prints no match text (main.rs:757-770), the TUI redacts the highlighted span too and fails closed in snapshot mode for any schema it cannot prove is ≥1.2 (app.rs:142-152). Cache stores `matched_len` and recovers text from the file.
- **Terminal-injection defense.** `sanitize_for_terminal` (findings.rs:128-171) escapes C0/C1/DEL and the bidi overrides while leaving RTL letters alone — Trojan Source is closed, which most scanners still have open.
- **Panic surface on untrusted content is effectively empty.** Only 37 of the 1183 unwrap/expect sites are outside `#[cfg(test)]`, and each is an infallible serde, a startup constant, or behind a verified structural invariant. Char-boundary safety is defended three independent ways (`content.get(start..end)` before every position call, `is_char_boundary`/`floor_boundary` in the TUI, `checked_sub`/`.get()` throughout cache restore). The metric tree walk is iterative on purpose.
- **Determinism.** Single-threaded sorted walk, per-file results carrying walk index and re-sorted after the parallel phase, whole-tree engines over BTreeMaps, final canonical `(path, line, column, rule_id)` sort. Output does not move with worker count.
- **Cache design.** Entries live outside the scanned tree, are authenticated with a location-bound random salt, carry version and path scope, and every rejection path is a miss rather than an error or a stale answer. The salt-creation race is correctly serialized with the reasoning written down (cache.rs:849-873).
- **Exit-code contract.** Zero rules loaded, an unevaluable coverage gate, a damaged baseline and a failed save all exit 2 rather than 0; `--min-severity` is applied after the exit decision by construction; `emit`/`emit_err` keep a closed pipe from producing 101.
- **Release pipeline.** Commit-identity asserted in every qualification job and re-checked in `candidate_manifest.py publicize`; `registry_publish.py` downloads the published `.crate` back and matches both the registry checksum and `.cargo_vcs_info.json` against the candidate SHA; `archive_gate.py` refuses absolute/traversing/symlink members before writing a byte and runs the extracted binary against a runtime-generated credential; all actions SHA-pinned, both downloaded tools sha256-verified; per-target THIRD-PARTY-LICENSES that hard-fails on a crate with no license text.
- **Symlink handling in the walk** (walk.rs:597-608) — six dispositions, `OutsideRoot` refused before open, cycles detected, every link recorded with a stable reason. The rule loader is the one place this discipline was not applied (B3).

## 5. Unverified / coverage gaps

- **Static inspection only.** Nothing in this audit was executed. No scan was run, no memory or wall-clock figure was measured, no OOM or hang was reproduced. Every performance number in the findings is an extrapolation from code shape, including the load-bearing match counts behind the quadratic-column impact.
- **13 medium and 11 low findings never received an adversarial refutation pass** — the entire "Should fix soon" list below the first four items, plus B4. Their mechanisms are as read from source, but their severity and impact framing are unchallenged. Three earlier findings were refuted and dropped on exactly that kind of framing error, so expect attrition here too.
- **The whole TUI dimension is unverified.** No TUI session was run, no saved report was crafted, no signal was delivered, no terminal was wedged. B4, the panic-teardown race, the 20 Hz re-read and the missing signal handlers are all code-reading conclusions.
- **No large-repo evidence.** The project's own `docs/PRODUCTION_READINESS.md:654` lists "peak memory and scan time on a representative large repository" as unverified, and this audit did not change that. The scale ceiling in B2 and the duplication multiplier are asserted from allocation counting, not observed.
- **MSRV and non-Linux platform behavior unverified** — no 1.96 build, no macOS or Windows run; the platform gap claim rests on workflow text.
- **Supply chain state unknown as of today.** No advisory query was made against the pinned graph; "currently clean" reflects `deny.toml` strictness and CI history, not a fresh RustSec check.
- **Three dimensions returned no blocking defect** — concurrency/cache correctness, output contract/exit codes/public API, and CI/release/supply chain. That is a positive result for correctness, determinism and release engineering, but their resource-side and scheduling-side findings (unconditional duplication, `entry_hash` double copy, advisory cron, tag-path gap) are carried above rather than dismissed.
- **No fuzzing, no property tests, no adversarial corpus.** The 1186 tests are the project's own; no test anywhere covers a large file, a long line, a symlink inside a rule directory, brace-grouped imports, or the baseline-absorption case.
