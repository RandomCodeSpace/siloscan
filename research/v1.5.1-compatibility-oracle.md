# Siloscan v1.5.1 compatibility and performance oracle

- Date: 2026-08-31
- Decision ticket: [Freeze the v1.5.1 compatibility and performance oracle](https://github.com/RandomCodeSpace/siloscan/issues/58)
- Behavioral reference: `880d211a463e97eb3c188f957e5592d88f36dcf8`
- Product version reported by that build: `1.5.1`

## Decision

The Rust build from exactly
`880d211a463e97eb3c188f957e5592d88f36dcf8` is the replacement oracle. A v2
candidate may replace it only when the candidate preserves the reference
projection defined below, passes every black-box workflow in the command
matrix, and stays within 5% of the reference for both elapsed time and peak
resident memory on representative cold and warm scans.

The comparison is strict where v1.5.1 already has a contract and additive only
where this Wayfinder map has closed a decision. The currently approved JSON
additions are `report_kind`, `scope`, and `outcome`. An implementation ticket
may extend that allowlist only by linking a later closed decision from the map.
Unknown fields, changed meanings, reordered findings, changed fingerprints, or
a conveniently omitted slow feature fail the oracle.

This oracle does not select an implementation architecture. It measures the
shipped behavior from outside the process. It covers all six engines, all ten
AST languages, configuration and walk semantics, suppressions, fingerprints,
baselines, cache behavior, output formats, exit statuses, the CLI and TUI, and
the release platforms. Security measurements and a Go implementation are not
part of this contract.

## Reference provenance

The source commit is authoritative, rather than the release tag alone. The
v1.5.1 release tag points to
`6773a0bf959aa666aa1c908a0504c349c577f4fc`, while the requested oracle commit
also contains the later detection-corpus evidence. No runtime product source
changed between those commits, but the corpus did. The released Linux binary
therefore validates packaging and runtime equivalence; it does not replace the
pinned source checkout as the evidence source.

The v1.5.1 tag signature verified, its published SHA-256 checksum matched the
downloaded Linux archive, and the extracted `siloscan` binary produced the same
mixed-fixture JSON bytes as the source build. The
[v1.5.1 release run](https://github.com/RandomCodeSpace/siloscan/actions/runs/31151368024)
completed on Linux, macOS, and Windows.

The pinned commit's current
[GitHub CI run](https://github.com/RandomCodeSpace/siloscan/actions/runs/33348294251)
is not green. Windows build, test, and smoke checks and the Rust 1.96 MSRV check
passed. Clippy fails on unchanged code at
`crates/siloscan-core/src/cache.rs:1694` because Rust 1.98 newly reports
`chunks_exact_to_as_chunks` under `-D warnings`. That is pre-existing CI drift,
not v2 behavior and not work for this evidence ticket. It must be cleared by a
separate minimal change before the final candidate can satisfy the exact-commit
CI gate.

### Generated scale repository

The performance repository is generated rather than committing 4,096 copies
of one file. Its only source is the reference commit's
`crates/siloscan-core/src/lang.rs`, whose SHA-256 is
`53f38d5a9044dd55e8e0dd38bf5b9cdd3b49fcb9d46bda12d714a6cfd788c8fc`.
Create `src/00/sample_0000.rs` through `src/40/sample_4095.rs`, placing 100
files in each numbered directory except the final directory, which has 96.
Every file is byte-identical to that source. Copy `scale/siloscan.toml` into
the generated root. Keep `scale/ast.yaml` outside the scan root and pass its
parent with `--rules`.

```bash

rules_root="$scale_parent/rules"

cp "$oracle/scale/siloscan.toml" "$scale_root/siloscan.toml"

i=0
while [ "$i" -lt 4096 ]; do

  name="$(printf '%04d' "$i")"
  mkdir -p "$scale_root/src/$shard"
  cp crates/siloscan-core/src/lang.rs \
    "$scale_root/src/$shard/sample_$name.rs"
  i=$((i + 1))

(
  cd "$scale_root"
  find . -type f -print0 | sort -z | xargs -0 sha256sum \
    > "$scale_parent/manifest.sha256"
)
test "$(sha256sum "$scale_parent/manifest.sha256" | cut -d' ' -f1)" = \
  32e15ce82ca06db7643fc3162454782f593bcf7c8822aa7f46b744930b3b5fb4

/usr/bin/time -f '%e\t%M' -o /tmp/siloscan-time.tsv \
  ./target/release/siloscan "$scale_root" \
  --rules "$rules_root" --no-default-rules --no-cache --format json \
  > /dev/null
```

The resulting input is about 31 MiB and has 41 source directories and 4,097
scanned files including the config. The AST query parses but intentionally

## Output comparison rules

Compatibility is evaluated on a named projection. Do not compare a few counts
and call the reports equal.

### Human output

An existing explicit, stateless scan must match `golden/human.stdout`
byte-for-byte, including path form, ordering, severity, rule ID, summary,
metrics, escaping, newline, stderr, and exit status. The new report-path line
is allowed only when persistence was selected by the saved-report contract.

### JSON

Parse both documents first. For the v1.5.1 projection:

1. Require `schema_version` to remain `1.2`.
2. Remove the top-level product `version` value from both documents.
3. Remove only additive top-level fields explicitly approved by closed map
   decisions. The current allowlist is `report_kind`, `scope`, and `outcome`.
4. Fail on any other extra or missing field.
5. Deep-compare every remaining value and array position.

The complete v2 document must separately pass the contract that approved each
additive field. Normalizing a field out of the v1 projection is not permission
for malformed v2 metadata. Finding order, metrics file order, warnings,
skipped paths, ignored paths, suppressions, anchors, filters, redacted matches,
and all fingerprint strings remain exact.

Repeated identical candidate scans must also serialize to identical bytes.
The top-level product version is the only value normalized from the existing
document. Do not normalize paths, sort after the fact, round floats, or discard
messages to hide candidate nondeterminism.

### SARIF

Parse both documents, remove only `runs[0].tool.driver.version`, then require a
deep exact match. No SARIF addition is currently approved by this map. Result
ordering, locations, levels, rule metadata, fingerprints, suppressions,
metrics, invocation outcome, stdout, stderr, and status remain part of the
projection. Repeated candidate serialization must be byte-stable.

### Baselines and fingerprints

Baseline JSON is byte-exact. Every fingerprint in every human-independent
finding list is exact. A candidate must read the reference baseline without
moving a finding, and the reference must read the candidate baseline with the
same result. Additive saved-report metadata never enters a fingerprint or a
baseline.

### Help and errors

Help text is an interface inventory, not a whole-file hash gate, because v2
adds settled commands and flags. Every v1.5.1 command, option, alias, default,
conflict, value set, and exit behavior in the committed help captures must
remain. Additions need a linked closed decision. Error text should retain the
specific failing path or input and actionable cause; tests should assert stable
semantic fragments rather than OS-rendered error decoration.

## Performance gate

Absolute timings from one machine are diagnostic only. Replacement acceptance
uses paired reference and candidate samples in the same GitHub Actions job,
with the same runner image, Rust toolchain, optimization profile, input bytes,
CPU allocation, environment, and output destination.

### Measurement paths

Measure these path and cache-state pairs:

| Path | Required cache states |
| --- | --- |
| Unchanged explicit invocation in v1.5.1 and v2 | `--no-cache`, cold, warm |
| Pinned bare v1.5.1 versus bare v2 with `--no-save` | Cold, warm |
| Pinned bare v1.5.1 versus bare v2 with automatic save | Cold first publication, warm replacement |

The automatic-save measurement includes canonical JSON serialization,
synchronization, and atomic replacement. The no-save measurement proves the
new planning path independently from persistence.

`--no-cache` measures a scan with cache bypassed. A cold sample uses a new
empty cache directory for that sample. A warm sample uses a separate cache per
binary, seeded by one untimed identical scan. Report state and caches live
outside the generated scan root. Build both binaries before measuring, discard
stdout, retain stderr, and reject a sample if the command did not exit with its
expected status.

The explicit cache states use this command shape; the paired CI harness
substitutes each binary and writes each timing record separately:

```bash
common=("$scale_root" --rules "$rules_root" --no-default-rules --format json)

/usr/bin/time -f '%e\t%M' -o /tmp/no-cache.time \
  ./target/release/siloscan "${common[@]}" --no-cache > /dev/null

cold_cache="$(mktemp -d)"
/usr/bin/time -f '%e\t%M' -o /tmp/cold.time \
  ./target/release/siloscan "${common[@]}" \
  --cache-dir "$cold_cache" > /dev/null

warm_cache="$(mktemp -d)"
./target/release/siloscan "${common[@]}" \
  --cache-dir "$warm_cache" > /dev/null
/usr/bin/time -f '%e\t%M' -o /tmp/warm.time \
  ./target/release/siloscan "${common[@]}" \
  --cache-dir "$warm_cache" > /dev/null
```

Create a different `cold_cache` for every cold sample. Keep one seeded warm
cache per binary; never let candidate and reference read each other's entries.

Bare measurements must stay bare. Run from the scale root and do not pass a
path, `--rules`, `--format`, `--cache-dir`, or `--no-cache`: under the settled
CLI contract those options make the invocation explicit and stateless. On the
Linux performance runner, isolate cache and report state with XDG environment
roots outside the fixture instead:

```bash
reference_bin="$reference_root/target/release/siloscan"
candidate_bin=/absolute/path/to/candidate/target/release/siloscan

reference_cache="$(mktemp -d)"
candidate_cache="$(mktemp -d)"
candidate_state="$(mktemp -d)"

(
  cd "$scale_root"
  XDG_CACHE_HOME="$reference_cache" \
    /usr/bin/time -f '%e\t%M' -o /tmp/reference-bare.time \
    "$reference_bin" > /dev/null
)
(
  cd "$scale_root"
  XDG_CACHE_HOME="$candidate_cache" XDG_STATE_HOME="$candidate_state" \
    /usr/bin/time -f '%e\t%M' -o /tmp/candidate-no-save.time \
    "$candidate_bin" --no-save > /dev/null
)
test "$(find "$candidate_state" -type f | wc -l)" -eq 0
```

Fresh cache and state directories make that a cold no-save pair. For a warm
no-save pair, run each command once without `/usr/bin/time`, then time the same
commands against their own now-seeded cache directories.

For automatic persistence, use new per-binary cache directories and one new
candidate state directory. The reference remains a bare v1.5.1 scan. The
candidate also receives no argument or flag at all:

```bash
reference_cache="$(mktemp -d)"
candidate_cache="$(mktemp -d)"
candidate_state="$(mktemp -d)"

(
  cd "$scale_root"
  XDG_CACHE_HOME="$reference_cache" \
    /usr/bin/time -f '%e\t%M' -o /tmp/reference-bare-auto-pair.time \
    "$reference_bin" > /dev/null
)
(
  cd "$scale_root"
  XDG_CACHE_HOME="$candidate_cache" XDG_STATE_HOME="$candidate_state" \
    /usr/bin/time -f '%e\t%M' -o /tmp/candidate-auto-save.time \
    "$candidate_bin" > /dev/null
)
test "$(find "$candidate_state" -type f -name latest.json | wc -l)" -eq 1
latest="$(find "$candidate_state" -type f -name latest.json)"
jq -e . "$latest" > /dev/null
```

That first candidate run is the cold publication case. For the warm case, seed
both caches with one untimed bare scan, let the candidate create its first
`latest.json`, then time a reference warm scan and the candidate's replacement
scan. Assert one parseable `latest.json` after every timed candidate run. Use
fresh cache and state roots for every cold sample and separate persistent roots
for each binary's warm series.

### Sampling and decision rule

- Run one untimed warm-up for each binary/path/cache combination.
- Collect nine paired samples, interleaving binary order with an ABBA pattern
  so runner drift does not consistently favor one binary.
- Record wall-clock elapsed seconds and OS peak RSS for every process. On GNU
  systems `/usr/bin/time -f '%e\t%M'` supplies elapsed seconds and peak RSS in
  KiB; use the platform-equivalent OS measurement elsewhere.
- Compare candidate median to reference median separately for duration and
  peak RSS. Keep raw samples as a CI artifact.
- A candidate ratio greater than `1.05` is a suspected regression. Rerun the
  complete paired job once on a fresh runner. The same path/cache/metric above
  `1.05` on both jobs is a blocking regression.
- An externally noisy job is invalid, not a pass. Mark it invalid when runner
  telemetry shows throttling or unrelated contention, or when paired reference
  samples themselves exceed a declared 20% median absolute deviation. Rerun it.
- Faster results do not offset a slower path or higher RSS. Every required
  path and cache state passes independently.

Do not drop work, skip synchronization, narrow the scanned tree, change the
rule set, hide a feature behind a flag, or move completion into an unjoined
background task to meet the number. That would be a feature regression with a
fast benchmark.

### Observed reference measurements

The generated scale repository produced these Linux x86-64 medians from five
samples. They prove the procedure runs and expose cold-cache variability; they
are not portable acceptance thresholds.

| Cache state | Median elapsed | Median peak RSS |
| --- | ---: | ---: |
| `--no-cache` | 3.45 s | 231,472 KiB |
| Cold | 4.18 s | 231,616 KiB |
| Warm | 0.46 s | 183,248 KiB |

The cold samples ranged from 3.34 to 7.15 seconds while writing 4,096 cache
entries. That variance is why the final gate is paired, interleaved, repeated,
and based on ratios rather than these absolute values.

## Release matrix

The release gate retains the current archive targets:

| Target | Archive smoke requirements |
| --- | --- |
| `x86_64-unknown-linux-musl` | Extract and run all three binaries natively |
| `aarch64-apple-darwin` | Extract and run all three binaries on Apple silicon |
| `x86_64-pc-windows-msvc` | Extract and run all three `.exe` binaries on Windows |

Each archive must contain `siloscan`, `ss`, `siloscan-tui`, `LICENSE`,
`NOTICE`, `THIRD-PARTY-LICENSES`, and `README.md` with platform-appropriate
binary suffixes. Verify the published checksum, then run version and help for
all three binaries. Run one explicit mixed-fixture scan through `siloscan` and
`ss`; run the fixed-size live and snapshot PTY smoke through the TUI. For v2,
also run the bare save, atomic replacement, and same-command review workflow.

Release CI must exercise the extracted archive, not a target-directory binary
left over from the build job. A successful compile is not evidence that the
archive has the right files or that those files start.

## Acceptance and stop condition

A Rust v2 candidate may replace the oracle only when all of these are true on
the exact candidate commit:

1. The targeted engine, corpus, CLI, persistence, detection, TUI, and release
   checks described here pass without reducing existing assertions.
2. Every v1.5.1 explicit invocation retains its admitted scope, findings,
   fingerprints, baselines, cache behavior, normalized output, and status.
3. The bare journey implements only the additions approved by closed map
   decisions and remains offline.
4. A prior supported report and baseline remain readable, and a candidate
   baseline remains readable by the reference where the schema is unchanged.
5. All required performance ratios are at most 1.05, or a suspected result is
   cleared by the required fresh-runner repetition.
6. The extracted Linux, macOS, and Windows release archives pass their smoke
   workflows.
7. GitHub CI is green for that exact commit. An older green run, a different
   worktree, or local full-suite output is not a substitute.

This document freezes the oracle. It deliberately does not implement the
missing black-box harness, change product behavior, repair unrelated CI drift,
or claim that a future candidate has passed.
